# Threat Information Exchange Service

REST-сервис обмена информацией об угрозах на Go. Контракт описан в
[api/openapi.yaml](api/openapi.yaml); типы, интерфейс и маршруты echo генерируются через oapi-codegen.
Хранение — PostgreSQL, миграции применяются автоматически при старте.

## Быстрый запуск

Нужны Docker и Docker Compose v2:

```sh
cp .env.example .env
make up
curl http://localhost:8000/health
```

`make up` собирает образ и ждёт готовности приложения и PostgreSQL.
При занятом порте поменяй `HTTP_PORT` в `.env`.

В Docker авторизация **включена по умолчанию**. `.env.example` содержит демонстрационные ключи:

- reader: `local-reader-key-change-me` — только чтение;
- writer: `local-writer-key-change-me` — чтение, создание и замена записей.

Перед использованием вне локальной демонстрации замени ключи и пароль БД.
Например, новый ключ можно получить командой `openssl rand -hex 32`.
Ключи должны различаться и содержать от 16 до 256 байт. Они читаются из окружения
(`READER_API_KEY`, `WRITER_API_KEY`), не записываются в YAML и не логируются.
При изменении ключей пересоздай контейнер приложения командой `make up`.

```sh
make logs                 # логи приложения в JSON
make down                 # удалить контейнеры, сохранив данные
make up                   # поднять снова с прежними данными
```

Данные сохраняются в именованном volume. Полное удаление **вместе с данными**:

```sh
docker compose down --volumes
```

После инициализации БД смена `POSTGRES_PASSWORD` в `.env` не меняет пароль уже созданной роли.
Его нужно изменить в PostgreSQL либо заново создать пустое демонстрационное окружение.

## API

| Метод | Путь | Успех | Назначение |
|---|---|---|---|
| POST | `/info` | 201 | Создать запись с уникальным MD5 |
| GET | `/info/{md5}` | 200 | Получить полную запись |
| PUT | `/info/{md5}` | 200 | Полностью заменить редактируемые поля |
| GET | `/health` | 200 | Проверить живость процесса, без ключа и rate limit |

Для примеров ниже используются демонстрационные ключи. При смене ключей замени значения заголовков.

```sh
curl -i -X POST http://localhost:8000/info \
  -H 'X-API-Key: local-writer-key-change-me' \
  -H 'Content-Type: application/json' \
  -d '{"md5":"D41D8CD98F00B204E9800998ECF8427E","name":"Trojan.Win32.Generic","severity":"high","tags":["phishing"]}'

curl -i http://localhost:8000/info/d41d8cd98f00b204e9800998ecf8427e \
  -H 'X-API-Key: local-reader-key-change-me'

curl -i -X PUT http://localhost:8000/info/d41d8cd98f00b204e9800998ecf8427e \
  -H 'X-API-Key: local-writer-key-change-me' \
  -H 'Content-Type: application/json' \
  -d '{"name":"Trojan.Win32.Generic","severity":"low"}'
```

Ошибки возвращаются как `{"message":"...","details":"..."}`. Пустые details опускаются.
Внутренние детали 500 доступны только в логах, с идентификатором `X-Request-ID`.

| Код | Причина |
|---|---|
| 400 | Неверный хеш, JSON, поле, enum, формат имени или порядок дат |
| 401 | Ключ отсутствует или неверен |
| 403 | Reader пытается создать или изменить запись |
| 404 | Запись или маршрут не найдены |
| 405 | Метод не поддерживается |
| 409 | Такой MD5 уже существует |
| 413 | Тело запроса больше 64 КиБ |
| 429 | Превышен лимит запросов либо вместимость хранилища лимитера |
| 500 | Ошибка БД или другая внутренняя ошибка |

## Модель и принятые решения

Обязательные поля создания — `md5` и `name`. При обновлении обязателен только `name`.

| Поля | Зачем добавлены |
|---|---|
| `sha256` | Дополнительный современный идентификатор файла; у MD5 известны коллизии |
| `type`, `platform` | Категория поведения и целевая платформа |
| `severity` | Приоритет реагирования |
| `status` | Возможность отозвать вердикт или отметить ложное срабатывание |
| `file_size` | Дополнительный признак файла; ноль отличается от неизвестного размера |
| `description`, `tags` | Контекст для аналитика и гибкая разметка |
| `first_seen`, `last_seen` | Период наблюдения угрозы |
| `created_at`, `updated_at` | Серверное время создания и последнего обновления записи |

- MD5 и SHA-256 приводятся к нижнему регистру. Регистр MD5 не создаёт новую запись.
- Уникальность MD5 гарантирует PRIMARY KEY PostgreSQL. Нарушение `23505` для этого ключа
  превращается в 409; предварительного SELECT перед INSERT нет, поэтому гонки создания нет.
- SHA-256 не является отдельным уникальным ключом и не вычисляется сервисом: файлы здесь не загружаются.
- PUT полностью заменяет редактируемые данные: опущенные опциональные поля удаляются,
  `type`, `platform`, `severity` получают `unknown`, `status` — `active`, `tags` — `[]`.
  MD5 и `created_at` сохраняются. `updated_at` меняется при успешном обновлении.
- Неизвестные опциональные значения отсутствуют в ответе. `file_size: 0` сохраняется и возвращается.
  Для очистки поля через PUT его нужно опустить; JSON null в контракте не предусмотрен.
- Имя проверяется по описанной в спеке форме нотации Kaspersky. Это намеренное ужесточение
  исходного строкового поля; регулярка не претендует на полный каталог всех исторических детектов.
- Тип и платформа не выводятся из имени: например, MSIL не задаёт однозначно нашу категорию ОС.
- Даты наблюдения не могут быть в будущем, `last_seen` не может предшествовать `first_seen`.
  Сравнение выполняется в сервисе, время нормализуется в UTC. PostgreSQL хранит микросекундную точность.
- Форму запросов проверяет OpenAPI-валидатор; бизнес-правила и дефолты проверяет сервис.
  Неизвестные поля в запросах запрещены. Сервис не зависит от echo, сгенерированных DTO и SQL.

## Архитектура

```text
cmd/threatintel -> internal/app: конфиг, сборка зависимостей, запуск и остановка
HTTP -> handlers/v1 -> service -> repository/postgres -> PostgreSQL
          API DTO       domain           SQL
```

`internal/domain` содержит модель и enum. Интерфейс репозитория объявлен в сервисе,
интерфейс сервиса — в хендлере, на стороне потребителя.
Ошибки передаются через обёртки `%w`, HTTP-коды выбирает общий обработчик ошибок.

Миграции из `db/migration` встроены в бинарник через embed и применяются до открытия HTTP-порта.
Повторное применение не меняет существующие данные. Ошибка БД или миграции останавливает запуск.
SIGINT и SIGTERM запускают graceful shutdown: сначала завершаются HTTP-запросы, затем закрывается пул БД.
Ожидание запросов ограничено таймаутом; при его превышении соединения закрываются принудительно.

## Защита и конфигурация

В `.env` для Docker доступны:

| Переменная | По умолчанию | Значение |
|---|---|---|
| `HTTP_PORT` | 8000 | Порт на хосте, также при TLS |
| `POSTGRES_PASSWORD` | threatintel-dev | Пароль БД для локальной демонстрации |
| `LOG_LEVEL` | info | Уровень логирования |
| `AUTH_ENABLED` | true | Проверять API-ключи |
| `READER_API_KEY` | local-reader-key-change-me | Ключ чтения |
| `WRITER_API_KEY` | local-writer-key-change-me | Ключ чтения и записи |
| `RATE_LIMIT_RPS` | 10 | Средняя частота запросов с одного IP |
| `RATE_LIMIT_BURST` | 20 | Допустимый кратковременный всплеск |

Для демонстрации исходного API без ключей можно явно выставить `AUTH_ENABLED=false`.
Локальный конфиг `config/local/config.yaml` также отключает авторизацию по умолчанию.
Rate limit включён в обоих профилях.

Лимитер использует token bucket из `x/time/rate`, работает до проверки ключа и ограничивает
в том числе неавторизованные попытки. На отказ возвращается 429 с `Retry-After`.
У каждого процесса своё хранилище: максимум 10 000 IP, неактивные записи удаляются
при обработке запросов с периодом 10 минут. Ключи сравниваются через SHA-256 и constant-time compare.

Адрес берётся из TCP-соединения: `X-Forwarded-For` и `X-Real-IP` не считаются доверенными.
За NAT клиенты делят лимит. Перед размещением за reverse proxy нужна явная настройка доверенных
прокси; распределённый rate limit для нескольких реплик в этом задании не реализован.

Настроены таймауты чтения заголовков, запросов, записи ответа и idle-соединений,
ограничение тела 64 КиБ, recovery паник. Контейнер работает без root, с read-only корневой
файловой системой, сброшенными capabilities и no-new-privileges.
HTTP-порт привязан к 127.0.0.1, PostgreSQL наружу не публикуется.
`/health` проверяет живость HTTP-процесса; отдельной проверки готовности БД на каждый probe нет.

## TLS

Для локальной демонстрации HTTPS с самоподписанным сертификатом:

```sh
make certs
make up-tls
curl --cacert certs/server.crt https://localhost:8000/health
curl --cacert certs/server.crt \
  -H 'X-API-Key: local-reader-key-change-me' \
  https://localhost:8000/info/d41d8cd98f00b204e9800998ecf8427e
```

Сертификат действует 7 дней, включает localhost и 127.0.0.1. Повторный `make certs` не перезаписывает
существующие файлы. Они исключены из git и контекста Docker-сборки, монтируются только для чтения.
Демонстрационный ключ имеет права чтения для UID контейнера; не используй его как production-ключ.

Приложение допускает TLS 1.2 и новее. Пути задаются парой `http_server.tls.cert_file` /
`http_server.tls.key_file`; ошибка чтения сертификата останавливает запуск.
Docker overlay `docker-compose.tls.yaml` передаёт эти пути и заменяет healthcheck на HTTPS.
Только локальный healthcheck самоподписанного сертификата отключает проверку доверия;
примеры curl проверяют сертификат через `--cacert`.

Остановка HTTPS-профиля:

```sh
docker compose -f docker-compose.yaml -f docker-compose.tls.yaml down
```

Для внешнего развёртывания нужны собственные доверенные сертификаты либо TLS на reverse proxy.
Автоматическое получение сертификатов и mTLS не реализованы.

## Разработка и проверки

Нужен Go 1.26.5. Локальный запуск с PostgreSQL описан в [db/README.md](db/README.md).

```sh
make all               # закреплённый линтер, юнит-тесты с -race, сборка
make test-integration  # PostgreSQL в testcontainers; нужен запущенный Docker
make generate          # генерация типов и echo-сервера
make check-generate    # проверка актуальности без изменения рабочих файлов
make lint-openapi      # Redocly CLI; нужны Node.js и npx
make verify            # все перечисленные проверки
```

Юнит-тесты не требуют Docker. Они проверяют конфиг, сервис с фейковым репозиторием,
хендлеры с фейковым сервисом, авторизацию, лимитер под конкурентной нагрузкой и TLS handshake.
Интеграционные тесты отмечены build-тегом `integration`: контейнер создаётся на случайном порту
и удаляется после проверки. Они проверяют SQL, конкурентные дубли, миграции up/down,
HTTP-цикл с реальной БД, роли доступа и соответствие ответов OpenAPI.

Время сервиса и лимитера подменяется в тестах, поэтому для проверки дат и восстановления
токенов не нужны sleep. Генератор изолирован в отдельном Go-модуле
[tools/oapi-codegen](tools/oapi-codegen/README.md): обновление kin-openapi в приложении
не ломает закреплённый oapi-codegen v2.5.0. Сгенерированный файл коммитится в репозиторий.
